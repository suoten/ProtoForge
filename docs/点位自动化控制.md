# 点位自动化控制指南（REST API）

> 适用版本：v1.6.x 及以上。本文面向**用脚本 / CI 自动化驱动仿真设备**的用户：自动写点位值、强制固定值、注入故障、切换设备状态，配合上位机或自动化测试框架完成闭环验证。
>
> 交互式 API 文档：服务启动后浏览器打开 `http://localhost:8000/docs`（FastAPI Swagger，可直接试调），完整 OpenAPI 规范见仓库根目录 `openapi.json`。

## 1. 准备：登录获取 Token

API 需要鉴权，写入类操作需要 **operator 及以上角色**。先用账号换 JWT：

```bash
curl -X POST http://localhost:8000/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username": "admin", "password": "admin"}'
```

返回：

```json
{
  "access_token": "eyJhbGciOi...",
  "refresh_token": "...",
  "token_type": "bearer",
  "username": "admin",
  "role": "admin"
}
```

之后所有请求带请求头：`Authorization: Bearer <access_token>`。

> demo 模式默认 admin/admin；正式模式（`protoforge run`）密码随机生成，见启动横幅。Token 过期用 `POST /api/v1/auth/refresh` 换新。

## 2. 找到设备和点位

```bash
# 设备列表（拿到 device_id）
curl http://localhost:8000/api/v1/devices -H "Authorization: Bearer $TOKEN"

# 点位元数据（拿到 point_name、address、data_type、access、生成器配置）
curl http://localhost:8000/api/v1/devices/{device_id}/config -H "Authorization: Bearer $TOKEN"

# 点位运行值（name、value、timestamp、quality、simulated）
curl http://localhost:8000/api/v1/devices/{device_id}/points -H "Authorization: Bearer $TOKEN"
```

关键元数据字段（来自 config 接口）：`name`（点位名，写接口用）、`address`（协议地址）、`data_type`（bool/int16/uint16/int32/float32…）、`access`（r=只读 / w=只写 / rw=可读写）、`generator_type`（值生成模式：sine/random_walk/fixed/script 等）。运行值接口只含当前值与质量戳，改地址/类型看 config，读写值看 points。

## 3. 写单个点位（最常用）

```bash
curl -X PUT http://localhost:8000/api/v1/devices/{device_id}/points/total_flow \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"value": 123.4}'
```

写入规则（平台会按点位 `data_type` 自动归一，非法值直接 400 并说明原因）：

| 点位类型 | 可接受的写法 | 注意事项 |
|---|---|---|
| bool | `true`/`false`、`"true"`/`"false"`、`1`/`0`、`"on"`/`"off"` | bool 点位**落在线圈区（0xxxxx）**，主站须用 FC01 读、FC05 写，FC03 读保持寄存器看不到它 |
| int16/uint16 等 | 数字或数字字符串 | 超范围自动钳制到类型边界 |
| float32/float64 | 数字或数字字符串 | float32 占 2 个寄存器 |
| 只读点位（access=r） | — | 返回 403，外部客户端写也会被协议层拒绝（异常码 0x01） |

常见错误码：`400` 值非法/缺 value；`403` 只读点位；`404` 设备或点位不存在；`409` 设备处于 ERROR/MAINTENANCE/PROGRAM 状态不可写；`500` 协议服务器拒绝写入。

响应里有个重要提示字段：若 `"protocol_active": false`，说明协议服务没启动，写入只改了内存值，**外部客户端看不到**——先 `POST /api/v1/devices/{device_id}/start` 把协议跑起来再测。

## 4. 写入 / Force / Reset 的区别（自动化脚本最容易混淆）

| 接口 | 行为 | 典型用途 |
|---|---|---|
| `PUT /devices/{id}/points/{name}` | 写一次新值，该值会被记住（外部写入缓存），生成器不再覆盖 | 模拟"人工置数"后保持 |
| `POST /devices/{id}/points/{name}/force` | 把点位**钉死**在固定值，每个刷新周期重新施加，压过生成器输出；body 传 `{"value": null}` 释放 | 调试时冻结某个点位；重启后失效（不持久化） |
| `POST /devices/{id}/points/{name}/reset` | 清除该点位的外部写入缓存，恢复生成器动态输出 | 让点位"活"回来 |
| `POST /devices/{id}/points/reset-all` | 恢复该设备全部点位 | 测试用例 teardown 复位 |

```bash
# Force 示例：把温度钉在 25.0，直到释放
curl -X POST http://localhost:8000/api/v1/devices/{device_id}/points/temp/force \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"value": 25.0}'

# 释放
curl -X POST http://localhost:8000/api/v1/devices/{device_id}/points/temp/force \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"value": null}'

# 查看当前全部被 Force 的点位
curl http://localhost:8000/api/v1/devices/{device_id}/forces -H "Authorization: Bearer $TOKEN"
```

## 5. 故障注入 API（自动化异常测试）

```bash
curl -X POST http://localhost:8000/api/v1/devices/{device_id}/faults \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"fault_type": "sensor_drift", "duration": 30}'
```

`fault_type` 常用值：`sensor_drift`（传感器漂移）、`sensor_stuck`（卡死）、`comm_loss`（通信中断）等；`duration` 单位秒，**-1 表示永久**，到时自动恢复。用 `GET /faults` 查看已注入的故障，`DELETE /faults/{fault_id}` 手动清除。

## 6. 设备状态机控制

```bash
curl -X POST http://localhost:8000/api/v1/devices/{device_id}/state/transition \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"event": "fault", "reason": "模拟设备故障，验证上位机报警逻辑"}'
```

可用事件：`start` / `stop` / `startup_complete` / `stop_complete` / `fault` / `reset` / `maintenance` / `maintenance_complete` / `program_mode` / `program_exit` / `device_failure`。非法转换返回 409。当前状态看 `GET /devices/{id}/state`，历史轨迹看 `GET /devices/{id}/state/history`。

## 7. 自动回路（control-loops）

对过程类仿真（温度/压力/流量），可建一个控制回路让平台自动把测量值（PV）向设定值（SP）靠拢，输出写到指定点位：

```bash
curl -X POST http://localhost:8000/api/v1/devices/{device_id}/control-loops \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"loop_id": "temp_ctrl", "loop_type": "simple", "setpoint_point": "temp_sp", "measurement_point": "temp_pv", "output_point": "heater_out"}'
```

`loop_type` 支持 `simple` / `cascade` / `feedforward`。UI"仿真场景"页配置的联动规则与这里是同一套数据。

## 8. 完整自动化测试示例（pytest）

```python
import requests

BASE = "http://localhost:8000/api/v1"

def login():
    r = requests.post(f"{BASE}/auth/login",
                      json={"username": "admin", "password": "admin"})
    r.raise_for_status()
    return {"Authorization": f"Bearer {r.json()['access_token']}"}

def test_upper_computer_reads_written_value(headers):
    # 1. 写点位：模拟温度上升到 85 度
    r = requests.put(f"{BASE}/devices/my-modbus/points/temp",
                     json={"value": 85}, headers=headers)
    assert r.status_code == 200 and r.json()["protocol_active"] is True

    # 2. 用你自己的 Modbus 客户端（如 pymodbus）从 40001 读回
    #    ... 客户端读取并解析 float32 ...
    # assert abs(value - 85) < 0.1

    # 3. teardown：恢复生成器动态输出
    requests.post(f"{BASE}/devices/my-modbus/points/temp/reset", headers=headers)
```

配合 CI：测试前 `docker run -d ... suoten/protoforge` 起服务 → `POST /devices/batch/start` 批量启动设备 → 跑用例 → teardown 复位。

## 9. 定时变化脚本（让点位"动"起来）

```python
import math, time, requests

BASE = "http://localhost:8000/api/v1"
H = {"Authorization": "Bearer " + requests.post(f"{BASE}/auth/login",
        json={"username": "admin", "password": "admin"}).json()["access_token"]}

while True:
    t = time.time()
    value = 50 + 20 * math.sin(t / 10)          # 50±20 的正弦波动
    requests.put(f"{BASE}/devices/my-modbus/points/temp",
                 json={"value": round(value, 2)}, headers=H)
    time.sleep(2)
```

> 更省事的做法：不改脚本，直接在点位上配生成器（sine/triangle/random_walk/script 等模式，UI 点位编辑里设置），平台会自己持续产生动态值，脚本只在关键断言时刻用 Force 钉值。

## 10. 常见坑速查

1. **写入成功但客户端读不到** → 看 `protocol_active`，协议服务没启动；或写到了 bool 点位却在读保持寄存器（bool 在线圈区）。
2. **写了值过几秒又变回去** → 该点位配置了生成器，改用 `/force` 钉值，或 `/reset` 前先理解生成器节拍。
3. **float32 读出来乱码** → 该点位占 2 个寄存器，确认起始地址后按 4 字节解析，且别让相邻点位地址重叠（保存时平台会拦截重叠）。
4. **401** → Token 过期，重新登录或 refresh。
