# 实战记录：汇川 HMI/上位机对接 EtherNet/IP 仿真，一个月打通全程复盘

> 本文整理自一次持续近一个月的真实联调（2026-10-20 ~ 11-17）：一位做汇川生态集成的工程师，需要让汇川触摸屏/上位机工具对接"AB ControlLogix 型"的 EtherNet/IP 从站，但现场没有随时可用的真实 AB PLC——于是全程使用 ProtoForge 仿真替代真机。
> 对接过程中的每一个坑，最后都变成了产品里不再存在的坑。这就是"被真实用户锤过"和"闭门造车"的区别。

## 场景

- 客户端侧：汇川 HMI（InoTouchPad 组态）、汇川 Demo 工具（PCCC 方式读写标签）、欧姆龙 NJ501
- 服务端侧：ProtoForge 的 AB（EtherNet/IP CIP）从站仿真，监听 `0.0.0.0:44818`
- 目标：标签名读写、中文标签、多设备共存、RTU over TCP 数据源

## 第一阶段：链路模型澄清（10-20）

第一个误区是"仿真从站要填 IP"——不需要。ProtoForge 模拟的是从站（服务端），创建设备后即监听等待主站来连，唯一要填 IP 的是**主站那一侧**（填运行 ProtoForge 的机器 IP + 44818）。多台设备共用一个监听入口，客户端按标签名找设备，重名永远命中先建的——多设备用点位名前缀区分（`PLC1_xxx`/`PLC2_xxx`）。

## 第二阶段：连接卡死三连修（10-21 ~ 10-22，v1.6.34–v1.6.39）

这是最曲折的一段，客户端反复"卡死/扫描失败"。通过开启 `raw_frames` 导出帧日志逐帧比对，定位出三个独立问题：

1. **握手空帧被静默**：客户端建连后先发一个空帧握手，服务端此前把这类帧当心跳静默掉了，客户端卡在握手阶段——一个读请求都发不出来。v1.6.36 恢复应答。
2. **扫描应答状态码差异**：服务端对"扫描查询"回 `01` 时客户端直接发标签读，回 `14` 反而把客户端带进死胡同分支。v1.6.37 按抓包回退到实测可用行为，并用真实报文做了完整回放验证。
3. **PCCC 方式读写（0x4B）**：汇川 Demo 读写标签用的是 `Execute_PCCC`（0x4B，报文直接带标签名），不是标准 CIP 符号化读写（0x4B/0x4C/0x4D）。v1.6.34 起支持按标签名读写（含中文）；v1.6.39 又修掉了"地址填数字导致按地址而非按名称注册"的匹配问题。

**经验**：这类问题的通用解法不是反复重试，而是——开 `raw_frames`（注意：高级配置是启动参数，**改完必须停止再启动协议**才生效）→ 复现一次 → 导出帧日志 → 对照 0x0065（注册会话）/0x006F（未连接，Forward Open）/0x0070（已连接数据）三类报文逐条看。日志会把"卡在哪一步"钉死，不用猜。

**经验二**：客户端工具的 DLL 会缓存符号信息，服务端修好后必须**完全重启客户端工具**（不是点"清缓存"），否则看起来像"还是不行"。

## 第三阶段：读写通了，值不对（10-23 ~ 10-25，v1.8.2/v1.8.4）

链路打通后暴露出数据层问题：

- BOOL（1 字节）/INT16（2 字节）标签的**写请求被当成读请求忽略**——v1.8.2 修复；
- 字符串写入解析缺陷——v1.8.4 修复；
- 若干"读出来的值不对"最终定位为客户端侧显示问题（显示框残留旧内容、小数位/缩放设置），判据是：以仿真器设备页的"值"列为准，重启客户端重读验证。

**经验**：值不对时先分清"服务端存的就不对"还是"客户端显示不对"——前者看设备页值列/帧日志，后者重启客户端即可验证。另外注意：开了动态生成器的点位，外部写入只保持约 30 秒会被生成器覆盖，要固定值就把生成方式改"固定"。

## 第四阶段：中文标签与多模式（10-25 ~ 11-16）

- 中文实测通过：标签值与标签名均支持 UTF-8（一个中文字 3 字节）。但建议标签名用英文、标签值用中文——真实 PLC（罗克韦尔/欧姆龙）对变量名都有限制，混用将来迁移会踩坑。
- 客户端是"RTU 帧+CRC 直走 TCP"（pymodbus `framer=RTU`、串口服务器透传）的场景，v1.16.2 新增 `rtu_over_tcp` 链路模式（详见 [RTU over TCP：两种帧，两个端口](rtu-over-tcp-two-framers.md)）。
- 期间还修掉了一个配置双入口歧义（表单 Link Mode 与高级配置 mode 保存值打架）——v1.16.3 起保存时自动清理互斥字段。

## 结果与沉淀

- 全链路打通：汇川 HMI/编程软件/组态 ↔ ProtoForge（Modbus TCP / EtherNet-IP CIP / RTU over TCP）
- 一个月内推动仿真器新增的兼容能力，全部进入黄金用例回归，随版本发布
- 联调环境即装即用：不需要协调真机排期，问题定位从"看现象猜"变成"导帧日志逐字节看"

**给后来者的三句话**：

1. 客户端连不上仿真从站，第一件事开 `raw_frames` 导帧日志，而不是反复重试；
2. 单机联调主站地址填 `127.0.0.1`，回环不经过网卡和防火墙，最稳；
3. 客户端工具会缓存符号表，服务端改完点位/升级版本后，客户端必须完全重启。
