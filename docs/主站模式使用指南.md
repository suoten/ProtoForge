# 主站模式使用指南（v1.9.0）

> 主站（Master/Client）模式是 ProtoForge v1.9.0 的新能力：**主动拨出**连接
> 现场真实从站设备，按扫描周期轮询点位。此前 ProtoForge 只能做从站侧仿真
> （设备被你的程序访问）；主站模式后，ProtoForge 也能作为客户端去"采"真实设备。

## 主站模式能干什么

```
真实从站设备（PLC/电表/RTU）
        ↑ 拨出轮询（Modbus/S7/104）
ProtoForge 主站设备（点位 = 真实设备实时值）
        ↓ SCADA / 上位机 / 测试引擎按需访问
   ┌────┴─────────┬──────────────┐
   │ Modbus 采集   │ S7 读取      │ IEC 104 遥信（任意协议转换）
   └──────────────┴──────────────┘
```

- **协议转换免费获得**：真实 Modbus 电表的数据，SCADA 走 S7 读、调度走 104
  遥信——主站轮询一次，任何协议服务端都能读。
- **测试引擎直接断言**：既有"读点位 → 断言 → 记录报告"的自动化测试步骤对
  主站设备同样生效，无需新增测试步骤类型——真实设备固件回归自动化。
- **工程排障可靠**：断线指数退避重连、点位质量标记（good/bad）、轮询统计
  （成功/失败/最后错误）API 可查。

## 支持的主站协议

| 协议名 | 链路 | 地址格式 | 写远端 |
|---|---|---|---|
| `modbus_master` | TCP / RTU-over-TCP / 串口 RTU | HR100 / IR100 / C0 / DI0 / 4x / 40001…（与从站一致） | ✅ 寄存器/线圈 |
| `s7_master` | ISO-on-TCP（默认 102） | DB1.DBD0 / DB1.DBX0.0 / M / I / Q | ✅ DB 值与位 |
| `iec104_master` | TCP（默认 2404） | IOA 序号（点位地址填数字） | ✅ 遥控 C_SC / 遥调 C_SE |

## 快速上手：Modbus 主站轮询真实从站

1. **协议服务页**启动 `Modbus Master (TCP/RTU)` 服务（主站不监听端口，
   "启动"只是置运行态）。

2. **创建设备**，协议选 `modbus_master`，设备配置填写拨出目标：

   | 配置项 | 说明 | 示例 |
   |---|---|---|
   | `mode` | tcp / rtu_over_tcp / rtu | `tcp` |
   | `host` | 真实从站 IP | `192.168.1.100` |
   | `port` | 从站端口 | `502` |
   | `slave_id` | 从站地址（Unit ID） | `1` |
   | `scan_interval` | 扫描周期秒（0.1~3600） | `1.0` |
   | `timeout` | 连接/IO 超时秒 | `3.0` |

3. **配置点位**——地址记法与从站完全一致：

   | 点名 | 地址 | 类型 |
   |---|---|---|
   | temp | `HR0` | float32 |
   | pressure | `HR2` | int32 |
   | pump | `C0` | bool |
   | speed | `IR0` | uint16 |

4. **启动设备**。轮询开始后：
   - 设备列表实时显示真实设备的值；
   - 点位质量 good=最近一轮成功，bad=最近一轮失败；
   - 通过任意其他协议服务端读取同一设备即可实现协议转换。

5. **写远端**（可选）：对设备点位下发写操作，主站会写到真实从站
   （float32 等多寄存器类型自动按大端序拆寄存器）。

## S7 主站要点

- 设备配置：`host` / `port`（默认 102）/ `rack` / `slot`（TSAP 按标准
  `01{rack<<5|slot}` 组装，S7-1200/1500 通常 slot 0 或 1）。
- 点位地址：`DB1.DBD0`（双字）、`DB1.DBW2`（字）、`DB1.DBB4`（字节）、
  `DB1.DBX6.0`（位）、`M10.0` / `MW20` / `MD30`（M 区）、`I0.0` / `Q0.1`。
- 数据大端序（S7 网络字节序），连接序列与 snap7 一致（CR→CC→Setup→Read Var）。

## IEC 104 主站要点

- 设备配置：`host` / `port`（默认 2404）/ `common_address`（公共地址 CA）/
  `scan_interval`（总召周期）/ `timeout`。
- 点位地址填 **IOA 序号**（如 `1`、`3`），类型映射：
  bool→单点遥信（M_SP_NA）、float32→短浮点遥测（M_ME_NC）、
  int16→标度化遥测（M_ME_NB）。
- 每个扫描周期发送一次总召（C_IC_NA_1 QOI=20），收集所有遥测遥信直到
  激活终止（ACTTERM）；TESTFR 自动应答。
- 遥控/遥调：对点位下发写即触发 C_SC（单点遥控）或 C_SE（遥调），
  等待激活确认 + 激活终止双确认后才返回成功。

## 主站轮询状态查询

```bash
curl http://localhost:8000/api/v1/devices/master1/points
# 点位值 + quality（good/bad）

curl -X POST http://localhost:8000/api/v1/tools/decode-frame \
  -H "Content-Type: application/json" \
  -d '{"protocol": "modbus_tcp", "hex": "54 1D 00 00 00 06 01 03 00 00 00 0A"}'
# 报文字段级解析（9 协议），联调排障用
```

轮询统计（成功/失败计数、最后错误）随设备详情接口返回主站状态。

## 报文字段级解析器（配套工具）

粘一帧报文 hex，按协议逐字段展开（Wireshark 式），CRC16/CS/BCC 自动重算
校验，不符直接报错。覆盖 9 种协议：

`modbus_tcp` · `modbus_rtu` · `s7` · `iec104` · `dlt645` · `cjt188` ·
`fins` · `mc` · `mewtocol`

典型用途：现场抓包后逐字段排查驱动编码问题、核对功能码/地址/字节序、
教学演示协议结构。

## 常见问题

**Q：主站模式和从站仿真冲突吗？**
不冲突。同一个 ProtoForge 实例可以同时跑从站服务端（模拟设备）和主站
（采真实设备）——这正是协议转换的用法。

**Q：连不上真实设备会怎样？**
按指数退避自动重连（3s→60s 封顶），点位质量标记为 bad，轮询统计里
`last_error` 记录最后错误原因（连接拒绝/超时/非法响应等）。

**Q：串口 RTU 怎么配？**
`modbus_master` 设备配置 `mode: rtu`，`serial_port: COM3`（或
`/dev/ttyUSB0`），`baudrate: 9600`。RTU-over-TCP（串口服务器透传）用
`mode: rtu_over_tcp` + host/port。

**Q：扫描周期多少合适？**
现场轮询 0.5~5s 常见；协议转换场景 1s；断言测试场景可以到 0.1s（注意
真实设备负载）。轮询间隔受全局 tick 周期限制，过小不会更频繁。
